> **Summarecon Mall Bandung menggelar event hampir setiap hari, tapi tidak tahu berapa orang dan kendaraan yang sedang ada di lokasi.** Tiket (loket.com), gelang peserta, dan gate parkir berjalan sendiri-sendiri. Akibatnya atrium, parkir, dan toilet baru ditangani setelah penuh.

## 2. Masalah

### 2.1 Kondisi sekarang

```
  Penjualan tiket        Peserta masuk          Kendaraan masuk        Pemantauan
  ───────────────        ─────────────          ───────────────        ──────────
  loket.com              Gelang (visual)        Gate parkir manual     CCTV + 2 petugas
  data milik platform    tidak tercatat         plat diketik manual    baru tahu saat penuh
        │                      │                       │                      │
        └──────────────────────┴───────── tidak terhubung ─────────────────────┘
```

### 2.2 Akar masalah dan dampaknya

| Akar masalah | Dampak | Bukti |
|---|---|---|
| Data tiket berhenti di loket.com | Summarecon tidak tahu jumlah peserta per event | Pak Ade |
| Gelang tidak tercatat | Jumlah orang di atrium tidak diketahui | Pak Asep |
| Pemantauan manual (CCTV) | Penumpukan di Atrium Cibadag baru ketahuan setelah terjadi | Pak Asep |
| Gate parkir manual | Gate baru ditutup setelah penuh, kendaraan dialihkan ke bahu jalan. Saat ramai antrean tidak tertangani | Pak Asep, Bu Mei |
| Event memakai lahan parkir | Kapasitas parkir berkurang justru saat pengunjung paling ramai | Bu Mei, berita FKB |
| Penanganan reaktif | Toilet penuh, keluhan di medsos, sentimen negatif | Pak Ade |

### 2.3 Rumusan masalah

> **Tim operasional Summarecon Mall Bandung**, yang menggelar event hampir setiap hari, **tidak bisa memantau berapa orang dan kendaraan yang sudah masuk** karena tiket, gelang, dan gate parkir tidak terhubung ke satu sistem. Akibatnya, seperti saat **Festival Kuliner Bandung** dan **Roeang Kita**, atrium, parkir, dan toilet baru ditangani setelah penuh.

### 2.4 Persona

| Persona | Peran | Kesulitan | Yang dibutuhkan |
|---|---|---|---|
| **Pak Ade** (utama) | Manajemen, PIC Event | Tidak punya data peserta sendiri, approval lama, komplain baru diketahui dari medsos | Semua yang masuk tercatat dan bisa dipantau |
| **Pak Asep** | Security | Memantau keramaian hanya dari CCTV dengan 2 petugas | Tahu kapan area mulai penuh sebelum terlambat |
| **Bu Mei** | Petugas Parkir | Input manual motor tanpa plat, parkir penuh, kewalahan saat ramai | Perkiraan lonjakan kendaraan sebelum event |

### 2.5 Masalah kedua: approval event

Pak Ade juga menyebut **approval event yang lama** (2 divisi, banyak dokumen). Sesuai saran mentor untuk fokus ke satu masalah, approval event dijadikan **rencana pengembangan**, bukan masalah utama.

## 4. Solusi

**SMICC-TS: tiket dan check-in event milik Summarecon yang terhubung ke Command Center.** Setiap peserta tercatat saat masuk, dan manajemen melihat jumlah orang serta perkiraan kendaraan dibanding kapasitas secara langsung, sehingga bisa bertindak **sebelum** penuh.

### Pembeda dengan loket.com

| | loket.com (sekarang) | SMICC-TS |
|---|---|---|
| Fokus | Menjual tiket | Menjual tiket **dan** memantau orang di lokasi |
| Data peserta | Milik platform, terpisah per event | Milik Summarecon, satu dashboard untuk semua event |
| Event gratis / tenant | Tidak tercakup | Tetap tercatat lewat registrasi dan check-in |
| Gelang | Tidak terhubung | Check-in QR mencatat setiap peserta |
| Parkir | Tidak ada | Perkiraan tambahan kendaraan dari tiket terjual |
| Masalah di lapangan | Tidak ada | Anomali di gate otomatis jadi tiket insiden + SOP |

## 5. Hitungan Dampak

| Dampak | Rumus | Data yang ada | Yang masih kurang |
|---|---|---|---|
| Kapasitas parkir hilang saat event | slot dipakai event ÷ kapasitas | Mobil 2.000, 1 area ±800, FKB 34 hari | Kapasitas pasti Area Parkir Barat |
| Pendapatan parkir hilang | kendaraan ditolak × tarif × hari penuh | Parkir motor penuh di hari kerja | Tarif parkir, kendaraan ditolak per hari |
| Skala masalah | event per bulan × peserta per event | ±30 event per bulan | Rata-rata peserta per event |
| Reputasi | jumlah ulasan negatif soal parkir/antre/toilet | — | Hasil [scraping](scraping/README.md) |

Kalau Area Parkir Barat setara satu area (±800 kendaraan), FKB mengurangi kapasitas parkir mobil hingga **±40%** selama 34 hari. Angka ini **baru bisa dipakai setelah kapasitas Area Parkir Barat dikonfirmasi**.
